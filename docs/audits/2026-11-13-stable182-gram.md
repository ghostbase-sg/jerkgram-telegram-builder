## Native ownership and API boundary

Native GRAM uses `Int64` nanotokens, `formatTonAmountText`, `Wallet/TopGram`, WalletNavigationBalanceComponent and WalletCardComponent. Stars uses StarsAmount and engine state with an explicit `!ton` branch; none of those engine states are modified for GRAM.

The largest accepted amount is `9223372036.854775807` GRAM (`Int64.max` nanotokens). Unlike Stars' arbitrary whole-unit Int64, this native type requires rejecting multiplied overflow. No Double conversion or rounding. Incomplete/invalid input keeps the last valid persisted value, as Stars does.

WalletContext state, real balance, native transfer/payment/API values, previous-wallet balances, transactions/history, send availability, authorization and all operation handlers remain untouched. The existing `displayBalance` real-balance small-value normalization is retained whenever the override is off. With override on, exact local zero/fraction values are passed to the same native display components. Existing Wallet benefits surface `withAlphaComponent(0.45)` is unchanged.
