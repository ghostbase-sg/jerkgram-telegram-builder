# Native Saved tags: focused UI recon, 2026-11-11

## Recommendation

Keep the existing Saved Messages peer ChatController and its ChatHistoryListNodeImpl bubble renderer. Add a typed local filter and a dynamically selected local history provider inside that history node. Extend the native tag accessory strip with local catalogue chips, an always discoverable create/manage action, and local assignment from the message context menu/selection panel. A sheet may own catalogue CRUD and assignment; filtered messages stay in the same chat. Remove the added Search chooser and pushed ItemList result/assignment navigation. This is an architecture recommendation, not an implemented or device-verified change.

Retain the accepted account-local persistent index, actual Saved MessageIds, 45-row pages and three-page/135-row window. No Premium override, reaction mutation, fake cloud custom-tag bytes, global reaction spoofing, history scan, or official 500-result search path is needed.

## Why the screenshot can still show Get / Premium

The beta2 added route is `Chat/ChatControllerNavigationButtonAction.swift:504–526`: Search opens a choice, Local tags pushes jerkgramSavedTagsController. That route never replaces the official accessory strip. The native strip still subscribes only to cloud stats and routes non-Premium actions into the paywall. Merely enabling the existing local service cannot change those branches.

For the local Saved surface, put local chips and a plus/manage affordance in the native strip, including its zero-tag state. Suppress the cloud promo specifically while rendering the local strip domain. If cloud tags are also exposed, give them an explicit cloud entry/domain with their existing entitlement behavior. No local chip, plus action, context assignment or long press may share the cloud Premium callback. This makes local functionality discoverable without an enable switch, catalogue precondition or Search chooser.

The SavedMessagesScreen component is not the live chat owner. Do not spend this change rebuilding that shell or mounting a second ChatController.

## Narrow same-chat architecture

1. **Typed state:** extend existing HistoryFilter with a domain payload such as `.cloudReaction(MemoryBuffer)` / `.localSavedTag(String)`, retaining isActive. Cloud initializers may stay as adapters. Make exhaustive domain switches at every customTag consumer; never return empty/fake bytes for local tags. Keeping the domain inside the existing filter avoids introducing a second field through every large presentation-state copying initializer. A local domain must remain distinct through equality, toggling, search activation and clearing.
2. **UI-owned coordinator:** one small TelegramUI Saved-local-filter coordinator owns the accepted LocalSavedTagsService/provider for this actual Saved peer, subscribes to catalogue/revision updates, and supplies chip state plus bounded history snapshots. It starts for an eligible Saved surface and disposes on account/environment change and controller teardown. ChatControllerNode already owns a concrete ChatHistoryListNodeImpl, so the new override API can remain in TelegramUI. AccountContext protocol changes are unnecessary unless a later implementation demonstrates a public boundary need.
3. **History override:** add a local filter/provider promise or setter to ChatHistoryListNodeImpl. In beginChatHistoryTransitions select the local view signal before chatHistoryViewForLocation when an eligible typed local filter is active; clear it to resume default Saved history. Keep chatLocation as the actual Saved peer and subject unchanged. Preserve the existing message-item creation, bubble layout, media, selection and message-action pipeline.
4. **Real request contract:** the adapter must receive location/anchor, direction, cursor, visible boundary and generation, then emit a view/update plus earlier/later/loading metadata. Translate scroll thresholds into store-issued earlier/later cursor requests. For direct jumps outside the retained window, add an indexed seek/around operation if needed; the current provider only exposes cursor paging, so do not pretend its signal-only wrapper already supports arbitrary anchors. First ship latest-window filtering plus supported cursor traversal only if jumps are explicitly resolved by the implementation.
5. **Bounded adapter:** makePageProvider(tagId:) already holds at most three windows, tracks revision, drops stale generations and retains outer boundary cursors. Convert its retained messages to chronological MessageHistoryEntry values with real IDs, preserving grouping only among matching messages. Reuse ordinary history transition processing. Do not append every page or rehydrate an entire tag. Snapshot loading/end flags must describe the local membership stream; do not turn local pagination boundaries into cloud history holes/network hole filling.
6. **Restore behavior:** save the unfiltered visible anchor before activation; clearing/tapping the selected chip disposes the local provider and restores the normal chat near that anchor. Rapid chip switches need a new generation and immediate loading/empty state, with no old-tag flashes. Count updates and selected-chip deletion must invalidate or clear the active filter deterministically.

The signal-only customView branch is useful as an example of adapting MessageHistoryView into existing bubbles. Reusing ChatCustomContentsProtocol directly would require new kind semantics, mutation methods, subject/chat-location behavior and paging APIs, while risking custom-chat composer/read/navigation changes. Using a dynamic local override under the existing Saved peer is the smaller affected surface. This is a new seam, not a one-line source reassignment: source is currently immutable and several transition/read/load-more paths distinguish default/custom sources.

## Native assignment and catalogue management

The prepared beta2 context action (`ChatInterfaceStateContextMenus.swift:993–1006`) already captures current selected IDs or the actual current Saved message IDs, including albums. Its callback pushes the rejected controller. Replace that callback with a native assignment sheet/popover backed by the accepted selectionSummary and assign/remove APIs. Show unchecked / mixed / checked state, let the user create a tag there, commit the entire intended batch, and remain in the chat. Keep “remove from these messages” distinct from “delete tag everywhere.”

The selection hook in `ChatInterfaceStateInputPanels.swift:33–43` likewise pushes that controller; reuse its captured IDs and change presentation to the same assignment surface. The existing ChatMessageSelectionInputPanelNode local action can remain the discoverable batch entry. Retain per-message native actions, media actions and batch selection behavior.

Rename/delete/create may use an ItemList or text alert inside a sheet. Restrict the reused JerkgramSavedTagsController to catalogue editing if retained: its message result rows, filter navigation and pushed assignment flow are not part of the accepted UI. Native SavedTagNameAlertController requires reaction/media data, so it is not a direct local text-tag editor. Do not use cloud setSavedMessageTagTitle or reaction callbacks for local mutations.

## Concrete risks and verification seams

- **Unavailable indexed messages:** LocalSavedTagsContentRow.message is optional. The bubble view cannot silently drop nil rows while claiming the tag is empty or complete. Decide how the same chat displays bounded retry/loading/unavailable status without synthetic MessageIds, and preserve membership for uncached records. Rehydrate exact indexed IDs through the accepted service, never by scanning history.
- **Text search:** do not apply text only to the current 135-row window and label that full results. Either build an indexed local text query with its own cursor semantics or visibly clear/pause the tag filter when entering normal text search. Tag-only bubble filtering can use the existing store unchanged; arbitrary combined full-text filtering cannot be claimed.
- **Actions and anchors:** verify reply, forward, original-source navigation, album handling, long press, selection, jump-to-message and clear-filter restore on actual Saved IDs. No action may navigate using an original forward ID instead.
- **Source lifecycle:** verify local-to-local and local-to-default switches with pending Postbox/network work; cancelled generations and disposed account sessions must never publish into another filter/account. Confirm local boundary flags cannot start ordinary cloud hole fetches.
- **Bounded history:** create more than 500 memberships; traverse both directions beyond 135 rows; reverse after eviction; verify exact counts, no duplication/skips, <=45 fetched per page and <=135 retained rows. Check message ordering, scroll stability, changing membership and semantic deletion while a window is active.
- **Entitlement matrix:** non-Premium with zero cloud tags must see create/manage and local assignment immediately. Local chip tap, long press, context assignment and selection assignment must perform zero cloud tag/reaction mutations and show zero Premium paywalls. Test Premium/cloud coexistence without changing entitlement flags.
- **State robustness:** test empty catalogue, empty selected tag, rename, deleting selected tag, relaunch persistence, account/environment switch, accessibility labels, long titles, Dynamic Type and dark mode. The same chat/controller instance and bubble renderer must remain active throughout filtering.
