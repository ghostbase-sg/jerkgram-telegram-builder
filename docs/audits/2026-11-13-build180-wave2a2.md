## One proven defect / one product owner

`SettingsUI/Sources/GhostBase/GhostBaseSettingsController.swift`:

- `jerkgramAboutChannelState` resolves one channel and combines its history view with `viewTracker.polledChannel`.
- The About controller constructs two such signals, JerkgramApp and JerkgramCommunity, consumed by the controller's state subscription.
- Before: those two subscriptions persist while the controller is hidden in the navigation stack. Existing visibility hooks only handle diagnostics and Settings reload; they do not cancel About feeds. Controller destruction already disposes the state subscription; this is hidden lifetime work, not a proven deinit leak.
- After: `jerkgramVisibleFeed` emits its initial loading state before appearance, keeping native ItemList readiness. `didAppear` activates the feeds; `willDisappear` switches to `.never()` through native `mapToSignal`, disposing current channel/history work while retaining the last delivered state. Reappearance starts one fresh subscription per channel. Duplicate appearance notifications are ignored. Deinit closes the gate too.
- Callback captures a ValuePromise, never its controller. Non-About pages keep the existing single unavailable value and no visibility callback. No new timer, cache, storage lookup or global observer.

Native poll ownership can be shared with another visible Telegram screen. Removing this owner's two polling subscriptions does not claim that all network polling for these channels stops. Necessary visible chat polling is preserved.
